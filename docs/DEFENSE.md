# Подготовка к защите

## Почему такая архитектура

Разделение на frontend, backend и базу данных — стандартная трёхзвенная схема: интерфейс не работает с базой напрямую,
вся логика и проверка прав находятся на сервере. Внутри backend слои `routes → controllers → services` разделяют ответственность:
маршрут знает адрес, контроллер — формат запроса и ответа, сервис — правила и SQL. Это упрощает тесты и поддержку.
Приложение вынесено отдельно от запуска сервера (`app.js` и `index.js`), чтобы тестировать его без открытия порта.

## Вопросы и ответы

**Зачем PostgreSQL?** Данные связаны (пользователи, фильмы, жанры, списки), поэтому нужна реляционная СУБД с внешними ключами,
ограничениями и транзакциями. PostgreSQL бесплатна, надёжна и широко используется.

**Для чего Docker?** База запускается одной командой на любом компьютере с одинаковой версией и настройками, не нужно
устанавливать PostgreSQL вручную. Контейнеризована только база: приложению Docker не нужен, а усложнять проект не требуется.

**Что такое Docker Volume?** Именованное хранилище вне контейнера. Контейнер можно остановить, удалить и создать заново,
данные в томе `cineverse-data` сохранятся. Удалить их можно только явно: `docker compose down -v`.

**Почему не Kubernetes?** Он нужен для оркестрации множества сервисов и масштабирования. У проекта один контейнер с базой,
поэтому Kubernetes добавил бы сложность без пользы. Требований методички о нём нет.

**Как работает REST API?** Ресурсы имеют адреса (`/api/movies`), действия задаются HTTP-методами: GET — читать, POST — создать,
PUT — изменить, DELETE — удалить. Данные передаются в JSON, результат показывает код ответа: 200, 201, 400, 401, 403, 404, 409.
Сервер не хранит сессию: клиент присылает JWT-токен в каждом запросе.

**Как устроена авторизация?** Пароль хранится только как хеш bcrypt. При входе сервер выдаёт JWT, подписанный секретом.
Каждый защищённый запрос проходит `authRequired`: токен проверяется, пользователь читается из БД (так блокировка и смена роли
действуют сразу), затем при необходимости `adminRequired` проверяет роль. Скрытие кнопки в интерфейсе — только удобство,
настоящая защита на сервере.

**Как защищены данные от чужих?** `user_id` берётся только из токена, а не из запроса, и каждый запрос к личным данным
фильтруется по нему. Чужая подборка отвечает 404, чужой отзыв нельзя изменить (403).

**Как защита от SQL-инъекций?** Все значения передаются параметрами (`$1`, `$2`). Названия колонок для сортировки берутся
из фиксированного списка. Этот сценарий проверяется тестом.

**Что такое Unit, Integration и E2E?**
- Unit: проверяют одну функцию отдельно, без базы и браузера (валидаторы, форматирование, фильтры). Быстрые, их больше всего.
- Integration: проверяют, как части backend работают вместе: настоящий HTTP-запрос → маршрут → логика → PostgreSQL. Медленнее, среднее количество.
- E2E: проверяют сценарий глазами пользователя в браузере (регистрация, поиск, избранное). Самые медленные и хрупкие, поэтому их меньше всего.

**Почему пирамида именно такая?** Чем выше уровень, тем дороже и медленнее тест, и тем сложнее найти причину сбоя.
Основную работу делают дешёвые Unit-тесты, а дорогие E2E покрывают только главные пути.

**Как работает CI?** При push и Pull Request GitVerse запускает файл `.gitverse/workflows/ci.yaml`: ставит зависимости, проверяет TypeScript
и сборку, запускает Unit, затем Integration и E2E. Любая ошибка помечает запуск неуспешным, и дефект находят до слияния в `develop`.

**Зачем ветки main и develop?** `main` всегда стабильна и готова к выпуску. Разработка идёт в `develop` через ветки `feature/*`;
готовое проверяется тестами и вливается через Pull Request. Так незаконченный код не попадает в стабильную версию.

**Как устроены связи между таблицами?** Один ко многим: пользователь имеет много подборок, оценок, отзывов (внешний ключ `user_id`).
Многие ко многим: фильм имеет много жанров, жанр — много фильмов (таблица `movie_genres`); подборка содержит много фильмов
(`collection_movies`). `UNIQUE (user_id, movie_id)` не позволяет добавить фильм в список дважды.

**Что такое транзакция и где она используется?** Группа операций, которая выполняется целиком или не выполняется вообще.
Например, добавление в «Просмотренное» и удаление из «Посмотреть позже», создание фильма вместе с жанрами, применение миграции.

**Что такое миграции?** Пронумерованные SQL-файлы, которые изменяют схему базы по порядку. Применённые запоминаются,
поэтому повторный запуск ничего не ломает.

## Что честно сказать на защите

- Постеры отсутствуют: поле `poster_url` пустое, интерфейс показывает заглушки. Источник изображений можно подключить позже.
- Рейтинги в демо-данных рассчитаны по оценкам тестовых пользователей, это условные данные.
- Результаты тестов в пояснительную записку вносите только из ваших реальных запусков (`npm run test:coverage`, скриншоты CI).
